协议长度
--------

旧版协议一帧的数据长度最大的255，但现在的应用情况下，需要增加。实现的方法：

把协议的起始段0x88
0xFB分解，将0x88的低三位作为帧长度的高位扩展，这样长度最大为0x7FF（2k）。示例：一帧数据为0x89
0xFB 0xFA 0x45......0xFC
0xFC，0x89的低三位为0x1，则此帧的实际长度应该为0x145。

协议地址
--------

针对GPRS设备，帧控制码第一位作为当前设备的地址类型，0x6表示当前通讯地址为设备的短地址（32位），0xF表示当前的通讯地址为设备的MAC地址（64位）。

GPRS设备短地址格式：高16位设备地址，低16位设备组地址。

对于小无线，帧控制码第一位作为协议的传输类型，判断是否需要添加设备源地址。

分包续传
--------

针对某些应用例如软件远程更新，图片上传等，无法做到一次发送完成，需要分包传输，

定义以下规则，用于数据的分包续传：

1、开始分包传输之前，数据的发起方要把数据类型(用于表示当前数据的用途)，数据大小，数据分包的大小，分包的总包数发给接受设备，并等待确认后再开始发送数据包。

2、接受设备在收到一个数据信息表头时，如果接收设备正在处理此数据发送设备的分包续传任务，则清除正在进行的任务，新建一个分包续传任务。即接受设备对某个数据发送设备的分包续传任务只维持一个。

数据续传

考虑实际情况，且为了提高传输的效率，增加数据续传的功能，实现方案：在数据传输发生中断时，数据发送设备记录下当前任务的信息，当链路恢复后继续传输。

时间同步
--------

在设备和平台心跳时，会与平台同步时钟：上报的数据中包含设备的时间，如果设备和平台的时间差异大于1分钟，则在返回数据中的同步标示中的时钟同步的位置为1，同时在后面添加正确的时间。

/\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*

\* Name: u16GetCrc16

\* Description: 生成CRC16校验码

\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*/

u16 u16GetCrc16(u8 \*pu8Data, u16 u16Len)

{

u8 u8MSBInfo;

u16 u16CrcData;

u16CrcData = 0xFFFF;

while(u16Len\--)

{

u16CrcData = u16CrcData \^ \*pu8Data++;

for(u8 i= 0; i \< 8; i++)

{

u8MSBInfo = u16CrcData & 0x0001;

u16CrcData = u16CrcData \>\> 1;

if(u8MSBInfo != 0 )

{

u16CrcData = u16CrcData \^ 0xA001;

}

}

}

return u16CrcData;

}
